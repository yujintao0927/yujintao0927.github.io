### 1.2 渲染与数据流

```
main.tsx
  └─ HashRouter
       └─ App.tsx
            ├─ <CursorGlow/>              # 全局装饰
            ├─ <header> 导航              # nav 数组
            ├─ <Routes>                   # 路由表
            │    /            → Home
            │    /blog        → Blog
            │    /blog/:slug  → Post
            │    /gallery     → Gallery
            │    /about       → About
            │    *            → NotFound
            ├─ <footer>
            └─ <BackToTop/>               # 返回顶部

内容数据流：
  src/posts/**/*.md
     │  import.meta.glob('?raw')  ← 构建期把所有 .md 当字符串打包进 bundle
     ▼
  lib/posts.ts  →  js-yaml 解析 frontmatter → 输出 Post[]
     ▼
  pages/Home · Blog · Post 消费 posts[] 渲染
```

**关键点**：文章是**构建期**被打包进 JS 的（`import.meta.glob` + `?raw`），因此部署后是纯静态文件，无需运行时请求，天然适合 GitHub Pages。

### 1.3 路由与链接

使用 **HashRouter**，路由体现在 URL 的 `#` 之后：

- 首页：`https://xxx.github.io/#/`
- 文章列表：`/#/blog`
- 文章详情：`/#/blog/<slug>`（`slug` = 文章文件名去掉 `.md`）
- 相册：`/#/gallery`
- 关于：`/#/about`

### 1.4 构建与部署流程

```
本地:  npm run build  →  vite 编译 →  dist/（index.html + assets/* + .nojekyll）
线上:  git push main  →  GitHub Actions(deploy.yml)
         ├─ npm ci
         ├─ npm run build
         ├─ upload-pages-artifact(dist)
         └─ deploy-pages → 发布到 Pages
```

**⚠️ 必须满足的前提**（曾经踩坑）：仓库 `Settings → Pages → Source` 必须选 **GitHub Actions**。若选「Deploy from a branch」，会把 `main` 分支的**源码**直接发布（`index.html` 引用 `/src/main.tsx`，浏览器无法运行 → 空白页）。

## 4. 可扩展点与位置（如何加东西）

### 4.1 新增一篇文章
在 `src/posts/tech/` 或 `src/posts/life/` 下新建 `.md`，用 frontmatter：

```markdown
---
title: "文章标题"
date: "2026-10-10"
excerpt: "一句话摘要，会显示在卡片上"
category: "tech"        # tech | life，决定分类与标签颜色
tags: ["标签1", "标签2"]
cover: "https://...图片URL..."   # 可选，文章封面图
---

正文（Markdown，支持表格、代码块、图片等）
```

**规则与坑**：
- `slug` 取自**文件名**（不含目录、不含 `.md`），所以 **tech/ 与 life/ 下的文件名不能重名**，否则会互相覆盖。
- `category` 只能是 `tech` 或 `life`（类型定义在 `lib/posts.ts` 的 `Category`）。
- 文章会自动按 `date` 倒序排列，无需改代码。
- 内文插图用标准 Markdown 语法：`![描述](图片URL)`。

### 4.2 新增一个分类（如「读书」）
1. `src/lib/posts.ts`：给 `type Category` 联合类型加一项（如 `'reading'`）。
2. `src/pages/Blog.tsx`：给 `filters` 数组加一条过滤标签。
3. `src/index.css`：加对应的 `.pill--reading` 配色（参考 `.pill--tech` / `.pill--life`）。
4. 新建 `src/posts/reading/` 目录放文章。

### 4.3 新增一个页面
1. `src/pages/` 新建 `Xxx.tsx`。
2. `src/App.tsx` 的 `<Routes>` 加 `<Route path="/xxx" element={<Xxx />} />`。
3. `src/App.tsx` 的 `nav` 数组加导航项。

### 4.4 新增一个组件
在 `src/components/` 新建组件，在需要的页面里 `import` 使用。全局样式写到 `src/index.css`。

### 4.5 新增图片 / 相册
- **相册**：编辑 `src/data/images.ts` 的 `galleryImages`（数组元素含 `src`、`caption`）。
- **本地图片**：放进 `public/images/`，代码/文章里用相对路径 `images/xxx.jpg` 引用（注意：不要写 `/images/...` 绝对路径，配合 `base:'./'` 才能正确加载）。
- **图片优化建议**：上线前把本地图压成 WebP，控制体积（见 §6.4）。

### 4.6 扩展 Markdown 能力
在 `src/components/MarkdownRenderer.tsx` 给 `<ReactMarkdown>` 加 `remarkPlugins` / `rehypePlugins`（如数学公式 `remark-math` + `rehype-katex`、自动生成目录等），并配套加样式。

## 5. 使用教程

### 5.1 环境准备
- Node.js ≥ 18（建议 20+）
- Git

在仓库根目录（`site/`）下执行：

```bash
npm install
```

### 5.2 本地开发
```bash
npm run dev        # 启动开发服务器，默认 http://localhost:5173
```
改代码会热更新。

### 5.3 写文章
直接在 `src/posts/{tech|life}/` 下新增/修改 `.md`（格式见 §4.1），保存即生效（开发模式下）。

### 5.4 构建与本地预览
```bash
npm run build      # 生成 dist/
npm run preview    # 本地预览构建产物，默认 http://localhost:4173
```

### 5.5 发布上线
```bash
git add .
git commit -m "描述本次改动"
git push origin main
```
推送后 GitHub Actions 自动构建并部署（约 1 分钟）。**前提**：`Settings → Pages → Source` 已选 **GitHub Actions**（见 §1.4）。

## 6. 优化更新与迭代方向

### 6.1 性能（当前最大优化空间）
- **现状**：单个 JS 打包约 1.6MB（gzip ~450KB），主要来自 `p5.js` 与 `react-markdown`/`highlight.js`。
- **建议**：
  - 用 `React.lazy` + `Suspense` 对 `ArtHero`（p5）、`MarkdownRenderer` 做**按需加载/代码分割**；
  - `vite.config.ts` 配置 `build.rollupOptions.output.manualChunks` 拆分 vendor；
  - 相册图片懒加载已用 `loading="lazy"`，可继续加 `srcset` 多尺寸。

### 6.2 SEO
- **现状**：HashRouter + SPA，搜索引擎抓取弱、每篇文章没有独立 HTML。
- **建议**（若在意 SEO）：迁移到 **SSG** 方案（如 Astro / Next.js 静态导出 / VitePress），或至少补 `sitemap.xml`、每篇文章的 meta。

### 6.3 功能增强
- **评论系统**：接入 Giscus（基于 GitHub Discussions，无需后端）。
- **访问统计**：接入 Umami / Plausible（轻量、隐私友好）。
- **RSS 订阅**：构建时生成 `feed.xml`。
- **深色/浅色主题切换**：在 `:root` 基础上加 `data-theme` 变量覆盖（当前配色已集中，改造成本低）。
- **代码块复制按钮**：给 `MarkdownRenderer` 的 `<pre>` 加复制逻辑。
- **文章目录（TOC）**：解析标题生成侧边目录。
- **搜索**：文章少可做前端全文搜索（如 FlexSearch / MiniSearch）。

### 6.4 内容与图片
- **替换示例图**：当前封面/相册用的是生成图接口 URL（`src/data/images.ts` 里的 `coresg-normal.trae.ai`），建议换成**本地真实照片**（放 `public/images/`）或图床，避免外链失效。
- **图片优化**：用 `sharp` 等工具转 WebP，控制单图 < 300KB。

### 6.5 架构演进
- 若文章量大、需要更强 SEO/性能，可迁移到 **Astro**（保留 React 组件，`Content Collections` 管理 Markdown，图片自动优化），或 **Next.js 静态导出**（`output:'export'`）。
- 迁移时保留现有 `src/posts/**/*.md` 内容与 frontmatter 结构，成本较低。

### 6.6 迭代时的注意点（避免重复踩坑）
1. **Pages Source 必须 GitHub Actions**，否则线上空白（§1.4）。
2. 静态资源路径用相对路径（`base:'./'`），不要写 `/xxx` 绝对路径。
3. 文章文件名即 `slug`，**全局唯一**（跨 tech/life 不重名）。
4. 改字体要同时改 `index.html` 的字体加载与 `:root` 的字体变量。
5. 改样式统一走 `:root` 设计令牌，保持视觉一致。
